# Технічне завдання та специфікація uacrypto — проєкт

Виробник: **Укренерго цифрові рішення**. Ідентифікатор документа: UAcrypto-ТЗ-01.
Затвердження замовником та експертною установою ще не виконано.

## Призначення і межі

uacrypto — бібліотека Go `github.com/h0rn3t/uacrypto` для вбудовування в програмні
системи. Вона надає криптографічні операції та засоби обробки українських ключових
і підписаних форматів. Самостійного процесу, мережевого сервера, сховища довірених
коренів, користувацької автентифікації або політики доступу бібліотека не створює.

Криптографічна межа в цьому проєкті охоплює пакети модуля та їхній код `internal/`.
Go runtime, ОС, джерело ентропії, прикладна програма та її сховище ключів є
компонентами середовища. Остаточну межу об'єкта експертизи, зокрема кінцевий
бінарний артефакт, визначають при погодженні інтеграції.

`parity/`, `graft/`, тестові ключі та сертифікати — матеріали розроблення і перевірки;
вони не є виробничими ключовими документами чи засобом генерації ентропії.

## Функціональний склад

| Компонент | Функції та основні інтерфейси |
|---|---|
| `dstu4145` | іменовані криві ДСТУ 4145, генерація ключів, Sign/Verify, кодування, ECDH; `io.Reader` для випадковості, `PrivateKey.Destroy` |
| `gost34311`, `kupyna` | гешування через `hash.Hash`, MAC відповідно до API пакета |
| `gost28147` | `cipher.Block`, гамування, MAC, `Destroy` |
| `kalyna` | `cipher.Block` 128/256/512 біт, режими ДСТУ 7624, MAC, обгортання ключів, `Destroy` |
| `strumok` | `cipher.Stream` із ключем 256/512 біт і 256-бітним IV, `Destroy` |
| `pki` | X.509, CMS/CAdES, XAdES, ASiC, PAdES, TSP, OCSP, CRL, ключові контейнери; точний перелік експортованих API — godoc і README |

`gost3410` залишається допоміжним API сумісності та не включається автоматично
до заявленого криптографічного профілю: український набір параметрів для нього не
надано, параметри обирає викликач, окреме підтвердження сталого часу відсутнє.
Підтримка SHA/MD5 у зовнішніх ідентифікаторах чи застарілих сховищах не означає
дозволу створювати ними нові виробничі підписи або захищати ними паролі.

## Проєкт конфігурації випробувань

| Параметр | Значення |
|---|---|
| Основна платформа | Linux/amd64; конкретні ОС, ядро, CPU та середовище фіксуються протоколом |
| Додаткова платформа | Linux/arm64 для функціональних перевірок; часові висновки amd64 на неї не переносяться |
| Компілятор | Go 1.27.3, `GOTOOLCHAIN=local` |
| Стирання тимчасових секретів | `GOEXPERIMENT=runtimesecret` |
| Функціональна збірка | `CGO_ENABLED=0`; бібліотека використовує лише стандартну бібліотеку Go |
| Ентропія за замовчуванням інтеграції | `crypto/rand.Reader`; власний PRNG не є джерелом початкової ентропії |
| Ідентифікація об'єкта | ревізія, стан checkout, SHA-256 маніфесту файлів; перед поданням — чистий затверджений реліз і геш кінцевого артефакту |

Це конфігурація-кандидат для випробувань, а не вже погоджена область сертифікації.
Зміна компілятора, ОС, прапорців, кривих чи способу постачання потребує оцінки
впливу та повторного виконання застосовних випробувань.

## Вимоги до поведінки

1. Результати алгоритмів і кодування збігаються з незалежними векторами для заявлених параметрів.
2. Змінені підписані дані, підпис, MAC або геш спричиняють помилку перевірки.
3. За наявності ESS SigningCertificate/SigningCertificateV2 перший ідентифікатор зв'язує CMS із сертифікатом перевірки; неправильний геш чи issuerSerial відхиляються. Відсутність ESS у звичайному CMS сама по собі не оголошується CAdES-помилкою; відповідний профіль перевіряє інтегратор.
4. Некоректні PDF ByteRange, зокрема значення на межі `int64`, повертають помилку без panic.
5. API знищення стирають збережений секретний стан і блокують подальші секретні операції. Власні копії інтегратора та буфери похідних режимів мають окремий життєвий цикл.
6. Помилка випадковості або криптографічної перевірки не підміняється успішним результатом чи тестовими даними.
7. Успішна перевірка математичного підпису не є підтвердженням довіри, чинності сертифіката або кваліфікованості підпису.

## Приймання

Приймання технічного кандидата потребує проходження [методики](testing.md),
простежуваності результатів до конкретних файлів і збірки та закриття рішень
із [реєстру досьє](README.md). Державне рішення про відповідність, вид засобу та
допустимі умови застосування ухвалюється в межах обраної процедури оцінювання.
