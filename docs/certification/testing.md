# Програма і методика випробувань uacrypto — проєкт

Виробник: **Укренерго цифрові рішення**. Документ: UAcrypto-ПМВ-01.

## Об'єкт і передумови

Об'єкт — конкретна ревізія модуля у конфігурації зі [специфікації](specification.md).
У протоколі зазначають дату, виконавця, ревізію, локальні зміни, маніфест файлів,
ОС/ядро, архітектуру, модель CPU, Go та параметри збірки. Тестові ключі й
сертифікати є виключно контрольними даними. Мережеві перевірки виконують окремо
і не змішують із відтворюваними локальними тестами.

## Матриця вимог і перевірок

| Вимога | Джерело очікуваного результату / перевірка | Умова проходження |
|---|---|---|
| Алгоритми та кодування | зовнішні вектори в `*_test.go`, `kalyna/testdata`, `dstu4145/testdata`; джерела у README та THIRD_PARTY_NOTICES | усі заявлені випадки збігаються |
| Реальні українські формати | корпус ЦЗО, TSA, OCSP, сертифікати в `pki/testdata` | позитивні випадки прийняті, змінені дані відхилені |
| Прив'язка CMS до сертифіката | `TestVerifySignedDataCertificateSubstitution`, `TestCheckSignedAttrsCertificateBinding` | підміна без зміни підпису відхилена; V1, SHA-256 DEFAULT та явні алгоритми обробляються правильно; неправильні й дубльовані атрибути відхилені |
| Безпека меж PDF | `TestVerifyPAdESByteRangeOverflow`, `TestVerifyPAdESRejects`, `FuzzVerifyPAdES` | некоректні діапазони повертають error без panic |
| Знищення секретного стану | `TestDestroy` у `kalyna` і `strumok`, наявні тести Destroy інших пакетів | збережені секрети обнулено; повторне використання блокується |
| Контроль типових дефектів | vet, golangci-lint із конфігурацією репозиторію, race | немає діагностик і виявлених гонок |
| Профіль `runtimesecret` | окремий запуск `scripts/test-certification-profile.sh` на Linux | компіляція, vet та функціональні тести проходять у зазначеній конфігурації |
| Часові властивості | `internal/ctcheck` на Linux/amd64, з позитивним контролем витоку | статистичні тести проходять за правилами harness; зберігається повний лог |
| Сумісність | вибрані цілі `parity/Makefile`; версії та обсяг у `parity/README.md` | немає розбіжностей, усі пропуски й адаптації зафіксовані |

Успіх функціонального тесту не доводить сталого часу, достатності ентропії,
захисту від фізичних атак або відповідності всім вимогам стандарту.

## Команди локальної перевірки

З кореня репозиторію:

```sh
gofmt -l pki kalyna strumok
go vet ./...
go vet -tags ctcheck ./internal/ctcheck
golangci-lint run ./...
go test -race -count=1 ./...
go test ./pki -run '^(TestVerifySignedDataCertificateSubstitution|TestCheckSignedAttrsCertificateBinding|TestVerifyPAdESByteRangeOverflow)$' -count=1 -v
go test ./kalyna ./strumok -run '^TestDestroy$' -count=1 -v
go test ./pki -run '^$' -fuzz '^FuzzVerifyPAdES$' -fuzztime=30s
```

На Linux з Go 1.27.3:

```sh
bash scripts/test-certification-profile.sh
go test -tags ctcheck -count=1 -timeout 60m -v ./internal/ctcheck
```

Часовий тест у цій методиці виконують на Linux/amd64. Для перевірок 32-бітної
функціональності використовують окремий запуск Linux/386 без тверджень про
сталий час. Фазинг може зберігати знайдені регресії; запускати його в робочій
копії, призначеній для випробувань, із контрольованим бюджетом ресурсів.

## Форма протоколу

Для кожного запуску зберегти окремий запис: ідентифікатор вимоги, команду,
конфігурацію, час початку/завершення, код виходу, повний лог, фактичний
результат, висновок та виконавця. Відсутній або пропущений запуск позначати
«не виконано» з причиною; нульовий код виходу без виконаних тестів не є доказом.
Відомі базові дефекти відокремлювати від регресій кандидата.

Для остаточного подання заморозити затверджений реліз, сформувати пофайловий
SHA-256 маніфест і геш кінцевого артефакту та повторити застосовні перевірки.
Внутрішні тести, CI і цей проєкт методики не є протоколом державних експертних
досліджень. Метод дослідження ентропії, самотестування, контролю цілісності та
інші випробування погодженого класу доповнюються експертною установою.
